# SQL Views Optimizer

## Overview

The SQL Views Optimizer is an automated tool that analyzes SQL views for a given client and generates index recommendations to improve query performance. It intelligently identifies columns used in JOIN, WHERE, GROUP BY, and ORDER BY clauses, checks for existing indexes, and can automatically add new index entries to the ETL codebase.

## Features

- **Automatic View Discovery**: Finds all views matching the client's prefix pattern (e.g., `SWAU_CLIENT1834_*`)
- **Intelligent Analysis**: Parses view definitions to identify:
  - JOIN columns (highest performance impact)
  - WHERE clause columns (high filtering performance)
  - GROUP BY columns (reduces filesort operations)
  - ORDER BY columns (improves sorting performance)
- **Index Existence Check**: Verifies which indexes already exist to avoid duplicates
- **Performance Estimation**: Provides estimated performance gains for each index
- **Automatic Code Generation**: Generates properly formatted Python code
- **Auto-Modification**: Can automatically insert recommendations into source files
- **Database Awareness**: Correctly identifies whether tables belong to `evadb` or `evadb_stage`

## Usage

### Basic Usage (Dry Run)

To analyze views and generate recommendations without modifying files:

```bash
python sql_views_optimizer.py --client_id 1834 --firmcode SWAU
```

This will:
1. Query all views with prefix `SWAU_CLIENT1834_`
2. Analyze each view for indexing opportunities
3. Check for existing indexes
4. Display recommendations on screen
5. Save recommendations to text files:
   - `index_recommendations_sql_helper.txt`
   - `index_recommendations_upsert.txt`

### Auto-Modify Mode

To automatically modify the source files:

```bash
python sql_views_optimizer.py --client_id 1834 --firmcode SWAU --auto-modify
```

This will perform all the steps above AND automatically insert the recommendations into:
- `sql_helper.py` (CheckAndInitIndexesForXero method)
- `XEROBLUE - UPSERT.py` (CheckAndInitIndexes method)

**⚠️ Important**: Always review the changes before committing!

### Command Line Arguments

- `--client_id`: Client ID number (default: 1834)
- `--firmcode`: Firm code prefix (default: SWAU)
- `--auto-modify`: Automatically modify source files with recommendations
- `--dry-run`: Show recommendations only (default behavior, can be omitted)

## How It Works

### 1. View Discovery

The optimizer queries the `INFORMATION_SCHEMA.VIEWS` table in both:
- `evadb` (production tables)
- `evadb_stage` (staging tables)

It looks for views matching the pattern: `{FIRMCODE}_CLIENT{CLIENT_ID}_*`

### 2. SQL Parsing

For each view, the optimizer:
- Parses the SQL definition using `sqlparse`
- Extracts table and column references from:
  - JOIN conditions
  - WHERE clauses
  - GROUP BY clauses
  - ORDER BY clauses

### 3. Index Analysis

For each table/column combination:
- Checks if an index already exists
- Determines which database the table belongs to (`evadb` vs `evadb_stage`)
- Selects appropriate index function:
  - `Add_ClientTable_Index` for production tables (evadb)
  - `Add_StageId_Generic_Index` for staging tables (evadb_stage)

### 4. Performance Estimation

The optimizer estimates performance gains based on:
- **Type of operation** (JOIN > WHERE > GROUP BY/ORDER BY)
- **Number of columns** (composite indexes often provide greater gains)
- **Number of views benefiting** (more views = higher ROI)

Performance gain estimates:
- **JOIN indexes**: 50-90% improvement
- **WHERE indexes**: 40-85% improvement
- **GROUP BY/ORDER BY indexes**: 30-60% improvement

### 5. Code Generation

Generates properly formatted Python code with:
- Descriptive comments explaining the index purpose
- Performance gain estimates
- List of views that will benefit
- Correct function calls with proper parameters
- Appropriate indentation for each target file

## Output Files

### index_recommendations_sql_helper.txt

Contains code to be added to `sql_helper.py` in the `CheckAndInitIndexesForXero()` method.

Example:
```python
    # ==================================================
    # INDEXES FOR CLIENT 1834 - SWAU
    # Auto-generated by sql_views_optimizer.py
    # ==================================================

    # JOIN index for c1834_xeroblue_journals: OrganisationID,SourceId
    # Performance: VERY HIGH (70-90% faster composite joins) - Benefits 3 view(s)
    # Benefits views: SWAU_CLIENT1834_reconciliation, SWAU_CLIENT1834_transactions

```

### index_recommendations_upsert.txt

Contains code to be added to `XEROBLUE - UPSERT.py` in the `CheckAndInitIndexes()` method.

## Troubleshooting

### "No views found with prefix..."

- Verify the client_id and firmcode are correct
- Check database connection settings
- Ensure views exist in the database

### "Could not find insertion point..."

- The target file structure may have changed
- Manually add the code from the `.txt` files
- Check that the `except TypeError as e:` marker exists in the target functions

### "Index already exists"

- This is normal! The optimizer skips indexes that already exist
- It means your database is already well-optimized

### Connection Errors

- Verify database credentials in `config.py`
- Check `USE_AWS_DB` environment variable
- Ensure network connectivity to the database

## Technical Details

### Database Schema

The optimizer queries:
- `INFORMATION_SCHEMA.VIEWS` - For view definitions
- `INFORMATION_SCHEMA.STATISTICS` - For existing index information

### Table Detection

Tables are classified as `evadb` vs `evadb_stage` based on:
- Table name patterns (e.g., tables with 'stage' in the name)
- Can be extended with more sophisticated detection logic

### Index Naming

Index names are generated using:
- Table name + column acronyms + "_idx" suffix
- Truncated to 60 characters (MySQL limit)
- Example: `c1834_xeroblue_journals_OrgID_SrcID_idx`

## Limitations

1. **SQL Complexity**: Very complex SQL with subqueries may not be fully parsed
2. **Implicit Joins**: May not detect some implicit join conditions
3. **Dynamic SQL**: Cannot analyze dynamically generated SQL
4. **Performance Estimates**: Are approximations based on general patterns
